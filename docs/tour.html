Every screen, one at a time

pogo is nine screens and about thirty keys. Each tab below is one of them, captured from a real process — with the keys that work there underneath.

Requests

Where pogo lands. Requests are grouped by the API they went to and the environment they reached it through; the sidebar shows the same shape with counts, so what you have been calling is something you look at rather than something you remember.

Preview

The panel down the right is the request under the cursor: where it went, what it carried, what came back — and a short list of things worth knowing before you open it. It is not the inspector in miniature; it answers the question you actually have while moving the cursor, which is is this the one?

p show or hide it ⏎ open it properly e edit it

Why it failed

curl's diagnosis when the request never completed, and the API's own message when it did.

Whether it always fails

Every call to this same endpoint, as a sparkline of durations and a count of how many failed.

What it is carrying

The credential it sends (masked), the {{variables}} it depends on, and where the time went.

APIs and environments

Everything pogo concluded about your hosts, with the key to correct it beside it. Pin an environment, name an API, hide one you do not care about — each written to disk on the keypress that made it.

A open it⏎ show its requests p pin the environmentn name the API x hide it

Inspect

Five panes: overview, request, response, timing, raw. Bodies render as a JSON tree you can fold, and secrets are masked until you ask for them — the mask is a display choice, and the screen says so.

⏎ opentab next pane1–5 jump v tree · pretty · rawspace fold a node S reveal secretsy copy

Edit and run

The request as fields: method, URL, query, headers, body. Edits are applied to your original command rather than used to regenerate one, so a request carrying --cacert, --resolve or -k keeps every one of those when you change a header. Running it records a new entry. n opens the same screen blank, for a request that has never run — filed under a project if you name one.

e openn new⏎ edit the field← → change method ctrl+d remove a rowctrl+t raw curl ctrl+e $EDITORctrl+r run

Compare

Mark one request, press d on another. JSON-aware: reordered keys and reformatted whitespace are not differences, changed values are, and response headers are diffed too. After a replay the mark is already set, so “what changed?” is one keypress rather than four.

d mark, then d again to compare ↑↓ scrolld clear the mark

Timing

DNS, connect, TLS, waiting, downloading — straight from curl's own instrumentation, as proportional bars. Nothing is estimated: on a curl too old to report it, the pane says so instead of inventing numbers.

4 from the inspector

Search

Free text, or a filter. Selecting a row in the sidebar runs it as a search and shows you the query it ran — which is how the syntax gets learned without reading anything.

Command palette

The answer to “what else can this do?”. Every row carries its keyboard shortcut, so finding something by searching teaches the key — the palette is built to make itself unnecessary. Commands that cannot run right now are listed anyway, dimmed, with the reason.

ctrl+k open↑↓ choose⏎ run

Environments

Switch what {{variables}} resolve to. The picker shows what each environment holds for the API under the cursor, because an environment name is global but its values belong to one API. How variables work →

E open⏎ activate

Settings

The handful of decisions that are genuinely personal — theme, what gets redacted, whether to check for releases — plus where every file lives. Each change is written on the keypress that makes it. There is no save key, because there is no unsaved state to get wrong.

H then Settings⏎ change

Home

The shell above the list: how much history there is, how many APIs, what a request would run against — and the workspaces that are not the list. Requests is the recommended card, and the cursor starts there.

H from anywhere1–5 jump⏎ open

First run

Four steps describing the loop the tool is built around — shown once, and never again unless you ask for it from the home menu. A first-run screen that vanishes forever is a support burden.
