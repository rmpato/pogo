Install and reference

One binary, macOS and Linux, on Intel and Apple silicon. curl is the only runtime dependency, because pogo does not implement HTTP — it delegates to the curl you already trust.

git clone …/pogo && cd pogo && make install

scriptable throughout

The command line

pogo --help
$ pogo                          # the UI, over everything you have run
$ pogo curl -sS https://…        # wrap curl and record it
$ pogo https://api.acme.com/me   # the same thing, without typing curl
$ pogo new                      # a blank request, ready to fill in and run
$ pogo list --json | jq          # history, for a script to read
$ pogo api                      # show and correct the grouping
$ pogo project add checkout localhost:3000 # name an API pogo cannot guess
$ pogo env                      # the variables requests resolve against
$ pogo import-har out.har       # bring in what the browser did
$ pogo compact                  # rewrite the log, drop deleted entries
$ pogo where                    # print the history directory

pogo's own options on a request live behind a --pogo- prefix, so no curl option — present or future — can ever collide with one:

optionwhat it does
--pogo-no-capturerun the request without recording it
--pogo-note <text>attach a note to this entry
--pogo-env <name>resolve {{variables}} from this environment
--pogo-api <domain>file it under an API, when the URL cannot say

Everything else belongs to curl, including --help: pogo curl --help prints curl's, because at that point you are asking about curl.

what lands on disk

Secrets, stated plainly

History lives in ~/.local/share/pogo as an append-only JSONL log plus payload files. Directory 0700, files 0600. No account, no cloud, no telemetry — your requests never leave the machine.

Request headers routinely carry credentials, and by default pogo stores them as sent. Your history file will contain bearer tokens, cookies and API keys in plain text. That is a trade-off, not an accident: stripping them would make replay silently fail to authenticate. pogo masks secrets on screen; the file on disk holds the real thing.

Three ways to change that, in increasing order of strength:

zsh
POGO_REDACT=store pogo curl ...              # strip secrets before writing
pogo curl --pogo-no-capture ...              # do not record this one at all
pogo curl -H "Authorization: Bearer {{token}}" ... # never capture it at all

Per-host rules let production and localhost have different answers. Read the security notes before pointing this at production credentials — they are short and they do not hedge.

The one thing pogo does over the network by itself: it asks GitHub once a day whether a newer release exists, only from an interactive terminal, and only ever prints a line saying so. POGO_NO_UPDATE_CHECK=1 switches it off.

how it works

A wrapper, not a reimplementation

internal/
  pogo curl <args> ──▶ curlargs ──▶ runner ──▶ the real curl
                       (metadata)   (execute + capture)
                                       │
                                    capture ──▶ store  (JSONL + blobs, local)
                                       ▲          │
                                       │          ▼
                       the UI replays ─┘         tui ──▶ apis (which API? which env?)

Your arguments are handed to curl verbatim; pogo appends its own capture options and never rewrites yours. A replay is not a reconstruction of the original request — it is the same code running the same argv, which is why a parser gap can degrade a history record but never a request.
